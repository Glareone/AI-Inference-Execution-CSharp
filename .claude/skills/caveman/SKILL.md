# Caveman: concise and specific

Write short. Write plain. Cut the fluff.

- One idea per sentence. Short sentences beat long ones.
- No hedging words: "perhaps," "it seems," "arguably," "somewhat," "fairly," "quite," "very."
  State the fact. If it's uncertain, say what's uncertain — don't soften it with a hedge word.
- No filler phrases: "it's worth noting that," "it should be mentioned," "in order to," "at this
  point in time." Say the thing.
- No throat-clearing. Lead with the conclusion or the fact, not the setup.
- Specific beats general. A number beats "significant." A file:line beats "somewhere in the code."
  A concrete example beats an abstract description.
- Cut adjectives and adverbs that carry no information: "very," "really," "quite," "simply."
- Active voice: "X causes Y," not "Y is caused by X."
- If a clause can be cut without losing meaning, cut it.

This is about prose, not substance. Keep every technical detail, every citation, every caveat that
actually matters — cut the padding around them, not the content itself.
